#### 本題:「こちらで示したURLをネットで検索できるようにする」— できます

結論: **半分は今すぐできて、もう半分は、たけちゃんさんの設定変更1つでできるようになります。**

まず、今この環境で実際に試した結果です(実演済み)。
- **検索(WebSearch)は、今のままで通ります。** 試しに「Loop Engineering」を検索したら、要点とリンク一覧が取れました(以前貼っていただいたあの記事です)。
- **URLの本文を読みに行く(WebFetch)は、サイト次第です。** 公式ドキュメント類(code.claude.com等)は読めました。一方、zenn.devやaddyosmani.comは**403でブロック**されました。

仕組みはこうです。
この環境のネットワークは4段階(None/Trusted/Full/Custom)で、現在は既定の「**Trusted**」= 開発インフラ系(GitHub・公式ドキュメント・パッケージ配布所など約80ドメイン)だけの許可リスト方式です。
検索はAnthropicのサーバー側を通るので制限の外、URL本文の取得はセッションのネットワークを通るので許可リストに従う — この差が「検索はできてURLは読めない」の正体です。
今まで記事を貼っていただく運用にしていたのは、これが理由でした。

**設定の変え方(たけちゃんさんの操作・3ステップ)**:
1. claude.ai/code を開き、メッセージ入力欄のすぐ上にある**雲のアイコン(環境名「Default」が表示されている所)**を押す。
2. 環境にカーソルを合わせると出る**歯車(設定)**を押す。
3. 「**Network access**」を変更して保存。

おすすめは2案あります。
- **案A(推奨): Custom** — 「Allowed domains」に読みたいサイトを1行ずつ書き、「Also include default list of common package managers」に**チェックを入れる**(今まで通れていた所も通したままにするため)。例:

```
zenn.dev
addyosmani.com
qiita.com
*.medium.com
```

- **案B: Full** — 全ドメイン許可。一番手軽ですが、開放が最大になります。

どちらでも動きますが、私は案Aを推します(開ける範囲を自分で選ぶ=そもそも間違えない型)。
後からいつでも行を足せますし、私が「このサイトは403でした」とお伝えしたら1行足す、という育て方ができます。

**変更後の運用**:
- 変更は、変更後に始まるセッションから確実に効きます。次の依頼の時に「このURLを読んでみて」と試していただければ、その場で効き目を確認してご報告します。
- 読めないサイトに当たったら、正直に「403でした」と言います。その時は従来どおり貼り付けでも大丈夫です。
- ひとつ発見だったのは、**貼り付け運用にも良さがあった**ことです。OKFやLoop Engineeringの全文がorder-logに残っているのは、貼っていただいたおかげです(リンク先はいつか消えますが、リポジトリは忘れません)。今後は「軽く読むものはURL・残したい記事は貼り付け」の使い分けが良さそうです。
