> #### 11. Google マップの URL からの取り込み(今回実装)と、短縮URL の技術的な説明
>
> - 「その形から始める案」が分かりにくくてすみません。実装したので、形で説明します。観測点/目的点の欄(花火の打ち上げ点・My観測点/My目的点の行も)に貼って Enter すると、通信なしで座標になります。
>   - Google マップの地点の URL: https://www.google.com/maps/place/富士山/@35.3606,138.7274,15z/data=…!8m2!3d35.3606255!4d138.7273634… → ピンの座標(!3d/!4d)を読みます(@の後の数字は画面の中心なので、ピンがある時はピンを優先)。
>   - 地点を長押し(右クリック)して出る座標の URL: /maps/place/35°21'38.3"N+138°43'38.5"E/… や /maps/search/35.3606,138.7274 や maps?q=35.3606,138.7274 → そのまま読みます。
>   - ピンの無い URL: /maps/@35.3606,138.7274,15z → 画面の中心を読みます。
>   - Apple マップ: maps.apple.com/?ll=35.36,138.72 や /place?coordinate=35.36,138.72 → 読みます。Android の共有の geo:35.36,138.72 も。
>   - 度分秒: 35°21'38.3"N 138°43'38.5"E(Google マップの座標表示からコピーした形。北緯/東経の漢字・前置きの N/E・経度が先でも可)。
>   - 判定の順は、Plus Code → URL/geo: → 度分秒 → 「緯度,経度」 → Plus Code の短縮形 → 地名検索です。地理院の地名検索が止まっていても、URL・座標・Plus Code は動きます。
> - 短縮URL(https://maps.app.goo.gl/…)が技術的に難しい理由(クロスオリジンの件):
>   - 短縮URL を開くと、Google のサーバーが「本当の URL はこちら」という転送(HTTP 302 と Location ヘッダ)を返します。宙の辻が知りたいのは、この Location の中身です。
>   - ブラウザの JavaScript が他のサイト(maps.app.goo.gl)へ通信する時、応答を読んでよいかは相手のサイトが決めます(CORS=相手が Access-Control-Allow-Origin を返した時だけ読める)。maps.app.goo.gl はこれを返さないので、応答は「不透明」(status 0・URL も本文も空)になり、Location も転送先の URL も読めません。
>   - 「転送を追わない設定(redirect: 'manual')」にしても、返るのは opaqueredirect という中身の無い応答で、やはり Location は読めません。「no-cors」でも同じです。ブラウザがそう作られているので、宙の辻側の工夫では越えられません。
>   - 越える方法は「自分のサーバーを間に挟む」(たとえば Apps Script の UrlFetchApp で followRedirects を切って Location を読み、宙の辻へ返す)の1つだけです。ただし、利用者が貼った URL が自分のサーバーを経由する(プライバシーポリシーの改定が要る)・Apps Script の1日の枠を使う・通信先が1つ増える、という代償があります。「サーバー資源を持たない」方針に合わないので、私からは提案しません(備忘録に「採らない方針なら閉じる」と書きました)。
>   - 今回の作り: 短縮URL を貼ると、地名検索へ回さずに案内を出します: 「短縮URL は展開できません。Google マップでその URL を開き、アドレスバーの URL(google.com/maps/place/… の形)を貼ってください。緯度,経度・Plus Code・度分秒でも設定できます」。
>   - スマホでの近道: Google マップの地点を開き、「共有」ではなく、地点の詳細を下へスクロールして出る Plus Code(例: 9Q7X+2V 富士宮市)か、座標(長押しで上に出る「35.36062, 138.72736」)をコピーして貼るのが、一番手数が少ないです。FAQ の新しい Q にこの手順を書きました。
