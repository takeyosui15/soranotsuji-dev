### 回答 (2026-05-25) — 相手高度が観測点→目的点と目的点→観測点で異なる理由

#### 結論: バグではなく、球面計算の正しい結果です

相手高度が A→B と B→A で等しくないのは、**地球が丸い**ため、2地点の地平面 (水平面) の向きがそれぞれ異なることに起因する物理現象です。

#### 理論的根拠

三角形 O-P1-P2 (地心O、観測者P1、ターゲットP2) の内角の和は常に π:

```
∠OP1P2 + ∠OP2P1 + c = π
(alt_AB + π/2) + (alt_BA + π/2) + c = π
```

整理すると: **alt_AB + alt_BA = -c** (中心角の符号反転)

つまり、2地点間の視高度の和は常に **-c** (中心角) になり、**ゼロにはならない**のが正常です。

#### 数値検証 (東京タワー h=400m ↔ 富士山 h=3776m, 距離 97.7km)

```
TT→Fuji (見上げる): +1.6659°
Fuji→TT (見下ろす): -2.4304°
合計:                -0.7646°

中心角 c:            +0.7646°
理論値 (alt_AB + alt_BA = -c): -0.7646°
誤差: 0.0000000000° ← 完全一致 ✓
```

平面の地球 (c=0) なら `+1.7° と -1.7°` で対称になるはずですが、球面では中心角 c ≈ 0.76° の分だけ非対称になります。

#### 同じ高度 (h_A = h_B = 100m) でも非対称?

```
A→B: -0.3121°
B→A: -0.4524°
差:   0.1403°
```

同じ高度でも値が異なるのは、**緯度が異なると WGS84 楕円体上の地心距離が異なる** ためです:
- 東京タワー (lat=35.66°): R ≈ 6371.2 km → r = Reff + 100m
- 富士山 (lat=35.36°): R ≈ 6371.1 km → r = Reff + 100m

緯度差は 0.3° (約 33km) と小さいため r の差も微小ですが、中心角 c ≈ 0.76° を介して視高度に影響します。

#### まとめ

| ケース | 対称性 | 理由 |
|---|---|---|
| 平面 + 同じ高度 | alt_AB = -alt_BA (対称) | 地平面が平行 |
| **球面 + 同じ高度** | **alt_AB ≠ -alt_BA** (非対称) | **地平面の向きが c だけ傾いている** |
| **球面 + 異なる高度** | **alt_AB ≠ -alt_BA** (非対称) | 上記 + 高度差の寄与 |
| すべてのケース | **alt_AB + alt_BA = -c** (厳密) | 三角形の内角の和から導出 |

これは WGS84 楕円体ベースの厳密な計算で物理的に正しい結果です。もし「平面的な対称性」が必要な用途があれば、ご相談ください。

### 回答 (2026-06-15) — 辻検索の日付境界 (午前0時付近) 取りこぼしを修正

#### 原因

辻検索 Worker (`tsuji-search-worker.js`) の **1日のスキャン範囲が 0:00〜23:59 (1440分)** で、Pass 2 のリファイン (前後60秒) が日付境界をまたぐ際に以下の問題が発生:

1. 6/24 の Pass 1 で `s=0` (0:00) がベスト候補になる
2. Pass 2 で `-60秒` (= 6/23 23:59:00) をチェック → こちらの方が角距離が良い場合
3. `bestMatch.timeMs` が 6/23 側に移動
4. 結果として **6/24 の結果が 6/23 の時刻として出力** → 6/24 としての独立した結果が消失

パール富士のように月が深夜〜未明に目的点方向を通過するケースで、月の最接近が午前0時付近に起こると発症します。

#### 修正内容

Pass 1 のスキャン範囲を **前後1分拡張**:

```js
// 旧: 0分〜1439分 (ちょうど24時間)
for (let s = 0; s < stepsPerDay; s++) {

// 新: -1分〜1440分 (前後1分のマージン)
for (let s = -1; s <= stepsPerDay; s++) {
```

これにより:
- 6/24 のスキャンは 6/23 23:59 〜 6/25 0:00 をカバー
- Pass 2 のリファイン (-60秒) が日付境界をまたいでも、前日 23:58:00 まで確実にスキャン済
- 各日のスキャンが前後1分ずつ重複するが、結果は各日のベスト1件なので重複結果にはならない

#### 影響

- 計算量: 1日あたり 1440回 → 1442回 (0.14%増、無視可)
- 既存の結果に影響なし (午前0時付近以外のケースは変化しない)
- パール富士のように深夜〜未明に月が通過するケースで、6/24 が正しく検出されるようになります
