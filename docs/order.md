> - Hom/推山 は1つのボタンで3つの働き。どれになるかは「押す時に、その横の (°) の欄(観測点(°)/目的点(°)。「Plus Code、緯度,経度」と薄く書いてある欄)が空かどうか」と「登録済みかどうか」で決まります。

> #### 2. 「:自動更新」の動きについて(ご質問へのお答え)
>
> 結論: **「読み込み」を選んでも、読み込みが選ばれたままにはなりません。** 「保存」「読み込み」は、ダイアログを開いたその場の一回きりの操作で、向きが記憶されることはありません。
> 「:自動更新」が自動でするのは**保存(端末→ドライブ)だけ**です。端末の内容が変わってから約30秒後(または画面を閉じる・裏に回る時)に、「ドライブが前回の同期から進んでいなければ」保存します。進んでいれば(他の端末が先に保存していれば)勝手には上書きせず、👎 にしてダイアログに委ねます。読み込みは、自動では起きません。
> たけちゃんの例で追うと:
> 1. PC で作業。自動更新オンなら、変更のたびにドライブへ保存される。
> 2. スマホで開いてログイン → ドライブが新しいので 👎 → ダイアログで「②読み込み」を選ぶ(再読み込みされ、ログインし直すと 👍)。
> 3. スマホで設定を変える → スマホ側も自動更新がオンなら、約30秒後に自動で保存される(ドライブが最新になる)。
> 4. PC に戻って何か変える → PC の自動保存は「ドライブが進んでいる」のを見て止まり、👎 に。アイコンを押して「②読み込み」→ 以後また自動で保存。
> つまり今の作りは「端末を切り替えるたびに1回、読み込みを押す」必要があります。端末の内容を勝手に上書きしない安全側の作りですが、名前が「自動同期」に読めるのは、おっしゃるとおりです。
>
> #### 3. 「自動同期」の案(事前提示。進めてよければ GO を)
>
> - 名前: 「:自動更新」→「**:自動同期**」(チェックは1つのまま。既定はオフのまま)。
> - 規則: **片側だけが変わった時は、向きを自動で決める。**
>   - 端末だけ変わった → 保存(今のとおり)。
>   - ドライブだけ変わった(端末の内容は前回の同期から変わっていない)→ **自動で読み込み**。
>   - 両方変わった → 今のとおり 👎 にして、ダイアログで人が選ぶ(ここは自動にしません。どちらを残すかは人の判断)。
> - 読み込みの契機: ログインした直後(起動時)と、画面が前面に戻った時(別のアプリから戻った時)にドライブの更新日時を確かめる。
> - 1つだけ、知っておいていただきたい制約: 読み込みは「ページの再読み込み」を伴います(今の「②読み込み」と同じ作り)。第159からログインの鍵は端末に残さないので、再読み込みの後は 🈚️ になり、アイコンを一度押してログインし直すことになります。流れは「スマホで開く → ログイン → (ドライブが新しければ)自動で読み込み → 再読み込み → 🈚️ → ログイン → 👍」。今の「読み込みを押す」が「ログインをもう一度押す」に置き換わる形です。
>   - 再読み込み無しで反映する道(ドライブの内容を書き戻した後、画面の全部を読み直す)もありますが、画面の初期化が1本道ではないので、作り込みと検証が大きくなります(別ラウンド規模)。まず再読み込み方式で入れて、使ってみて気になるようなら次に、と考えています。

> 短い答え(詳しくは `docs/dessin/dessin/35-offline-storage.md`):
> - **アプリ本体は IndexedDB に入っていません。** 本体(HTML/JS/フォント)はブラウザの HTTP キャッシュだけ(GitHub Pages は10分)。IndexedDB にあるのは地理タイル・標高タイル(+可視マップ資産)・天気の控え、設定は localStorage。だから「開いたまま圏外」は動き、「圏外で開く」はできません。

> - **全削除ボタン**: 「端末のデータ」の一覧(本体の控え/設定/地理タイル/標高タイル/可視マップ資産/天気)に、行ごとの削除と全部削除を置きます。reset.html も本体の控えを消すように。
> - **自動の片付け**: ウェブには「閉じた後も動く裏方」はありません(あっても Chrome のインストール済み PWA 限定で当てになりません)。なので、開いている間に片付けます: 起動5秒後(1日1回)・前面に戻った時・「今すぐ整理」ボタン。削除はワーカーで、画面を止めずに。規則は「30日使っていない物を消す」+「店ごとの上限の9割を超えたら古い順に8割まで」。最終使用の記録は、読むたびではなく1タイル1日1回までにして重くしません。上限と使用率%は店ごとにアプリが数えます(ブラウザは「サイト全体」しか見ない)。
> - **IndexedDB は localStorage と同じでオリジン(スキーム+ホスト+ポート)ごとです。** ブラウザが容量不足で消す時は、サイトの全部をまとめて消します(店ごとではない)。だから店ごとの上限はアプリが持つしかありません。iOS の Safari は「7日間触らないと全部消す」規則があり、ホーム画面に追加した宙の辻だけ別勘定になります(圏外で使う人には「ホーム画面に追加」を案内するのが現実的)。

> #### 4. オフライン起動と端末のデータ管理(問いへの答え+デッサン35・案)
>
> 短い答え(詳しくは `docs/dessin/dessin/35-offline-storage.md`):
> - **アプリ本体は IndexedDB に入っていません。** 本体(HTML/JS/フォント)はブラウザの HTTP キャッシュだけ(GitHub Pages は10分)。IndexedDB にあるのは地理タイル・標高タイル(+可視マップ資産)・天気の控え、設定は localStorage。だから「開いたまま圏外」は動き、「圏外で開く」はできません。
> - **「常に最新を読みに行き、読めなければ控えから」は、そのとおり正解です。** それをするのが Service Worker。本体の控えは版ごとに名前を分け、新しい版が入ったら古い控えを捨てます。他のサイト(Google・地理院など)への通信には一切触りません(今の守りのまま)。
> - **全削除ボタン**: 「端末のデータ」の一覧(本体の控え/設定/地理タイル/標高タイル/可視マップ資産/天気)に、行ごとの削除と全部削除を置きます。reset.html も本体の控えを消すように。
> - **自動の片付け**: ウェブには「閉じた後も動く裏方」はありません(あっても Chrome のインストール済み PWA 限定で当てになりません)。なので、開いている間に片付けます: 起動5秒後(1日1回)・前面に戻った時・「今すぐ整理」ボタン。削除はワーカーで、画面を止めずに。規則は「30日使っていない物を消す」+「店ごとの上限の9割を超えたら古い順に8割まで」。最終使用の記録は、読むたびではなく1タイル1日1回までにして重くしません。上限と使用率%は店ごとにアプリが数えます(ブラウザは「サイト全体」しか見ない)。
