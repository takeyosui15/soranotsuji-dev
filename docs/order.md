> #### 7. セキュリティプラグインと、リポジトリを非公開にするか
>
> - Claude Code の公式のセキュリティのプラグインは2つあります(どちらも Anthropic の公式マーケットプレイス)。
>   - security-guidance: Claude がコードを書くそばから、同じセッションの中で自分の変更を見直す仕組み。①ファイルを編集するたびの危ない書き方のパターン照合(モデル呼び出し無し) ②ターンの終わりに差分を別の Claude がセキュリティの目で見る ③commit/push の時に周りのコードまで読む深い見直し。止めるのではなく、見つけた物を Claude に戻して直させます。入れ方は `/plugin install security-guidance@claude-plugins-official`。ただし「クラウドのセッション(Claude Code on the web=私がいつも動いている箱)はユーザー設定やリポジトリの .claude/settings.json のプラグインを読み込まない」と公式に書かれています。つまりたけちゃんの手元(ターミナル/デスクトップ/VS Code)の Claude Code には効きますが、この箱の私には効きません。
>   - claude-security: 「/claude-security」でリポジトリ全体(や差分)を複数のエージェントで走査し、脅威モデルを作って脆弱性を探し、独立した検証を通った指摘だけを報告書(Markdown/JSONL/SARIF)に書き、直しのパッチ案まで作る物(適用は人が git apply)。有料プランか API が要り、トークンを多く使います。
>   - 私の見立て: 宙の辻は第159の監査(Workflow 8視点)・verify184(合格条件を毎回自動で見張る)・毎ラウンドの反証レビューで、security-guidance の「書きながら見直す」に当たることは既にやっています。claude-security の「全体の深い走査」は、第159以来やっていない「もう一度の全体監査」として価値があります。入れるなら、たけちゃんの手元の Claude Code で `/claude-security` を一度回して報告書(CLAUDE-SECURITY-*/、.gitignore 付きで commit には入りません)を見る、が良いと思います。私の箱からはプラグインは使えないので、同じ事を Workflow で組んで回すこともできます(ご希望なら次のラウンドで)。
> - リポジトリを非公開にするか: 私は「公開のまま」を勧めます。
>   - 公開の利点: GPLv3 のソースなので隠す物が無い。note から order.md を直接読める(たけちゃんの便利さ)。GitHub の秘密情報スキャン・push 保護・非公開の脆弱性報告(PVR)は公開リポジトリなら無料で全部使えます(非公開リポジトリでは秘密情報の保護は有料の GitHub Secret Protection が要り、PVR は公開リポジトリ向けの機能です=公式ドキュメントに「公開リポジトリの所有者と管理者が有効にできる」とあります)。
>   - 非公開にしても安全性はほとんど上がりません: 攻撃の入口は「配信されているサイト」(誰でも読める JS)であって、リポジトリの公開/非公開ではありません。秘密情報(トークン・鍵)を入れない運用(push 保護・verify184 S6)の方が効きます。
>   - 非公開にする理由があるとすれば「開発中の文書(デッサン・todo・order.md)を見られたくない」場合ですが、それは note へのリンクの便利さと引き換えです。MederuU のように「施錠」したい物は別のリポジトリに分ける今のやり方で足りていると思います。
>   - 参考: 公式ドキュメントの要点は上のとおりです。URL は今回の回答の末尾(Sources)に。

ありがとうございます。
結局、リポジトリは、公開のままにします。
理由は、公開の利点と、非公開にしても安全性がほどんど上がらないこと、開発中の文章は、正直、あまり見られていしまうと、アイディアを盗られてしまう恐れがありますが、9月20日に公開して、過去28日間のインプレッション数:221、ビュー数:36、過去7日間のインプレッション数:72、ビュー数:5、なので、私も参照しているものも、おそらく含まれていると思うので、そんなに、見られているわけではないので、問題ない範囲だと思います。
あと、セキュリティープラグインについてですが、箱の中でやって、記録に残すことが、後になって、確認できるので、「同じ事(claude-security)を Workflow で組んで回す」ことをやりましょう。
リリースは、セキュリティ対策が済んでからにしましょう。
