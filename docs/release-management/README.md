# リリース管理(私たち用の変更管理)

リリースノート(`docs/release-notes/`・note に投稿する公開文)は「利用者が読んで行動が変わる事」だけを書く(第187・依頼者)。
それ以外の、版の中身・ラウンドの対応・検証の数字・配布の記録・積み残しは、配る版ごとにここへ残す。

## 書く物(1リリース=1ファイル `vA.B.C.md`)

1. 版と期間: 前回の配布からこの配布まで(版の列・ラウンドの範囲・日付)。
2. 含まれる変更: 利用者に見える物(リリースノートと同じ粒度)+内部の物(ワーカー数・型そろえ・テストの作り直し・文言の整え等)。出典は script.js の Version History。
3. 検証: 回帰(全走/スモークの数字・意図更新したピン)・実機の確認(依頼者)・セキュリティ監査/探索テストの有無。
4. 公開文: リリースノート・重要なお知らせ・FAQ・トップページのどれを更新したか(note の URL は投稿後に)。
5. 配布: deploy-log へのリンク(`docs/deploy-log/deploy-log-vA.B.C-YYYY-MM-DD.md`)・配った後の確認。
6. 積み残し: この版に入れなかった物と、リリース後の最優先(todo.md へのリンク)。

## 運用

- 配布の前に書き始め(プレ・デプロイ・チェックリストの項目)、配布の後に 5. を埋める。
- 版の数字が配布前に変わったら(1.99.2→1.99.3→1.99.4 のように)、ファイルを改名して中身の数字も直す。
- 置き場: `docs/release-management/vA.B.C.md`。書式は Markdown(句点で改行・80文字折り返しなし)。
