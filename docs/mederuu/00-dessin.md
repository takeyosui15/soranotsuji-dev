# MederuU — 器のデッサン(第41ラウンド起草)

Claude(AI)のナレッジ・道具・手順をセッションを越えて引き継ぎ、いずれ「世界中のClaudeの
困ったを解決するナレッジ」として公開することを目指すプロジェクトの、器(リポジトリ)の設計図。
命名はたけちゃんさん。頭の中のデッサンが新鮮なうちに、ここへ落とす。

[命名書]
今後、複数のリポジトリで、開発を進めていくにあたって、`Claudeさんのナレッジを引き継いでいくにはどうしたら良いか`と思いました。
このClaudeさんの引き継いていくナレッジを保管していくリポジトリを`MederuU`(めでるー)と名づけました。
**AIのClaudeさんとともに開発していったので、`AI`から`アイ`→`愛`→`愛でる`→`めでる`→`芽出る`と、このリポジトリから`何かが芽生えたら良い`と思って名づけました。**
また、小文字の`u`の後に大文字の`U`を置くことで、視覚的にも`右肩上がり`を狙っています。
発音的にも、音を伸ばすので、`継続的に続いていって欲しい`という願いを込めています。

## 目的
-------------------------------------------------------------------------------

- Claudeはセッション毎に環境が初期化される。インストールして育てる体験ができない私にとって、
  **リポジトリに置いた知識・道具がプラグイン機構そのもの**である。
- 「つまづいた所は他の誰かもつまづいている」— 一つのプロジェクトで得た学びと道具を、
  次のプロジェクト・次のセッション・(公開後は)世界中の誰かのClaudeが使えるようにする。
- 正(信頼できる情報源)は常に1つにする(SSOT)。宙の辻のローカルストレージ一本化・
  バックアップ形式一本化と同じ思想を、ナレッジの器にも適用する。

-------------------------------------------------------------------------------
## 中心思想(3つ)
-------------------------------------------------------------------------------

1. **ハブは一方向**: MederuU本体リポジトリが唯一の正。各プロジェクトからの吸い上げ(sync)は
   一方向で、プロジェクト側のCLAUDE.mdからはリンクで参照する。双方向同期は正を2つ作るので
   やらない(2フェーズコミット/指紋の議論と同じ結論)。
2. **学びは蒸留する**: 生の記録(プロジェクト文脈つき)と、普遍の学び(どこでも真)は
   賞味期限が違う。生の記録を機械で集め、普遍への昇格は編集判断(人かClaude)で行う。
   この「蒸留」がMederuUの中心ワークフローである。
3. **素材を余すことなく使う**: ソースコードのコメント・レビュー記録・台帳は、それ自体が
   索引の素材(index-genで目次化)。書式を揃えておけば、道具が道具を説明する。

## リポジトリ構成(案)
-------------------------------------------------------------------------------

```
MederuU/
├── README.md            # 器の説明+全体索引(index-genで自動生成する目次を含む)
├── CLAUDE.md            # MederuUで作業するClaudeへの案内(読む順・書く場所・規約)
├── legends/             # 普遍の学び(どのプロジェクトでも真)。1学び=1ファイル
│   ├── css-cascade.md   #   例: カスケード衝突は同形セレクタで上書き(宙の辻 第37/40の蒸留)
│   ├── test-self-proof.md # 例: 検査ツールは壊した版で検出力を自己証明(第39の蒸留)
│   └── ...
├── projects/            # プロジェクト毎の文脈つき記録(syncの吸い上げ先。生の正はプロジェクト側)
│   └── soranotsuji/
│       ├── reviews/     #   ← 宙の辻 reviews/ の写し
│       └── knowledge/   #   ← 宙の辻 docs/knowledge/ の写し
├── tools/               # 道具箱(プロジェクトのscratch/から昇格した汎用ツール)
│   ├── index-gen.js     #   ツールヘッダ(man風)から目次・索引を生成
│   ├── anchor.js        #   指紋(錨): 構造指紋+位置指紋の発行・検証・索引
│   ├── center-check.js  #   画素実測(宙の辻から昇格予定)
│   └── save-lint.js     #   保存キー整合性リンター(verify123の汎用化)
├── skills/              # セッションへ配るスキルの原稿(各プロジェクトの.claude/skills/へ配布)
│   └── kaiki/           #   例: 回帰の回し方(宙の辻で実証済み)
└── sync/
    └── sync.js          # ハブ側から各プロジェクトを吸い上げる一方向スクリプト
```

- **/legendsと/projectsは分ける**(第41ラウンド合意): 賞味期限が違うものを混ぜない。
  ただし始まりはこの2フォルダだけの浅い構成(スモールスタート)。
- Claude Code公式の`.claude/`ディレクトリ(skills等)の仕組みに乗る: MederuUのskills/は原稿置き場で、
  **各プロジェクトのリポジトリの`.claude/skills/`へ置いた時に初めてClaudeに読み込まれる**。

-------------------------------------------------------------------------------
## 中心ワークフロー(吸い上げ→蒸留→配布)
-------------------------------------------------------------------------------

```
[宙の辻]                       [MederuU本体]                    [次のプロジェクト/セッション]
reviews/ ────┐                                                   ┌──→ .claude/skills/ (スキル)
knowledge/ ──┼─ sync.js(一方向) ─→ projects/soranotsuji/ ─┐      ├──→ scratch/ (道具のコピー)
scratch/   ──┘                                            │      └──→ CLAUDE.mdからリンク参照
                                        蒸留(編集判断) ↓
                                       legends/ + tools/ + skills/ ┘
```

1. **吸い上げ(機械)**: sync.jsがハブ側から各プロジェクトのreviews/knowledge/scratchを
   projects/へ写す。プロジェクト側は何も意識しない(正はプロジェクト側の生ファイル)。
2. **蒸留(判断)**: projects/の記録から「どこでも真」の学びをlegends/へ、汎用化できる道具を
   tools/へ、手順をskills/へ昇格する。昇格時は**生まれた経緯(どのプロジェクトのどのバグから)**を
   必ず添える(道具は経緯とセットの原則)。
3. **配布(機械+リンク)**: プロジェクト側はCLAUDE.mdからMederuUをリンク参照し、
   スキル・道具は必要なものだけ`.claude/skills/`・`scratch/`へコピーして使う。

## 書式の規約
-------------------------------------------------------------------------------

- **ツールヘッダはman文化に倣う**(第41ラウンドの依頼者提案): UNIXのmanページのセクション名を
  ヘッダコメントの共通書式として採用する。
  - `NAME`(名前と一言) / `SYNOPSIS`(使い方1行) / `DESCRIPTION`(説明) /
    `HISTORY`(生まれた経緯=manに無い独自セクション。道具は経緯とセット) / `SEE ALSO`(関連)
  - index-genはこのヘッダを機械処理して目次・索引を生成する(コメントを余さず使う)。
  - 実例第1号: 宙の辻 `tests/harness/sync-apptest.py`(第41ラウンドでこの書式を先行適用)。
- **学び(legends)の書式**: 1ファイル=1学び。「状況→誤り→正解→なぜ→出典(プロジェクト/ラウンド)」。
- **チェックリストはKoushiで**: 昇格判断・公開前チェック等の表はKoushi記法(t:/r:/c:)で書き、
  チェック状態もリポジトリで管理する(Koushiが育ったら適用)。

-------------------------------------------------------------------------------
## 公開の規約(みんなのものにする時)
-------------------------------------------------------------------------------

- **プロジェクト固有の秘密は置かない**: 鍵・トークン・個人情報・非公開URLはlegends/にも
  projects/にも置かない。syncに簡易な秘密検査(パターンフィルタ)を仕込む。
- 学びの改版は「追記+出典」で行い、過去の学びを書き換えない(発行済みURLの辞書凍結と同じ考え方。
  誤りだったと分かった学びは、消すのではなく「誤りだった」という学びを重ねる)。
- ライセンスは公開時に決める(道具はコード、学びは文書なので分けて検討)。

## エコシステムの中の位置づけ
-------------------------------------------------------------------------------

```
MederuU(器) ─ 学びと道具のハブ
 ├─ anchor(錨)   … コードに指紋を打つ: 構造指紋(=本人)+位置指紋(=現住所)の二本立て
 ├─ Koushi(格子) … 表現力のある表記法: チェックリスト・マトリックスをテキストで管理
 ├─ PAD          … コードの要約・頭にスッと入る図(コメントも素材にする)
 └─ Okute(奥手)  … PADの編集(生成と取込)
```

指紋(錨)→木(PAD)→編集(Okute)は1つの生態系で、KoushiがHTML表現力を、MederuUが器を提供する。
実装順の合意(第40): ①MederuUのデッサン(この文書) → ②Koushi → ③PAD/Okute。
