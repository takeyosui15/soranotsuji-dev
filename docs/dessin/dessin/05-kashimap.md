## 可視マップメニュー

(第3版: 2026-09-15 第142ラウンド。依頼者の「伝わってこなかった」を受けて、**平易な言葉で
書き直した版**。第142の仕切り直し=「静的な可視マップ」と「動的な推し山サイト」の分離を反映し、
登山道ピンは可視マップから外した[ピンは推し山サイトの投稿型へ]。第1・2版はgit履歴に残る)

### まず一言で:
- 可視マップは、**「この山(推し山)は、どこから見えるか」を地図に塗った、一度作ったら変わらない地図**です。
- 宙の辻の中で見るための機能で、計算は別に(まとめて)やっておき、アプリはその結果を読み込んで表示するだけです。

### 用語(このデッサンで使う言葉):
- **推し山**: 見たい山(目的点)。可視マップの対象は百名山・二百名山・三百名山の基本リストだけ。
- **タイル**: 地図を格子に切った1枚。地理院の標高タイル(z15)に揃える。北緯35〜36°でほぼ**1km四方**。
  緯度で伸び縮みする(北海道で約0.89km・沖縄で約1.09km)。1タイルは256×256画素、画素は約3.9m間隔。
- **見える/見えない**: 各画素に「地上1.5mに立った人」を置いた時、推し山の山頂が見えるかどうか。
- **島**: 「見える」画素が地図上でひとかたまりになった区域。可視マップはこの島を一覧にする。
- **静的資産**: 一度計算して配る成果物。ユーザーの入力で変わらない(推し山サイトの投稿とは別物)。

### 目的:
- 推し山が「どこから見えるか」の全体像(島)を、地図上で一望できるようにする。
- 辻メッシュ検索(重なる日時を探す)の前段として、「そもそも見える場所」を教える。
- 推し山サイト(動的・投稿型)の土台データになる(島の形と場所を渡す)。

### 概要:
- 機能概要(依頼者の構想・第136〜142)
  - 対象と範囲
    - 対象は**基本リスト(百名山・二百名山・三百名山)のみ**。
    - 範囲は推し山を中心に**60km四方 / 100km四方 / 300km四方 / 700km四方**から選ぶ
      (最大700kmは、富士山が紀伊半島の潮岬から見えた実績に合わせた)。
  - 見える/見えないの判断(第139推奨案・依頼者承認)
    - 「見える」は、地形の丸み(地球の曲率)と大気差を入れた既存の可視判定で決める。
    - 遮るものは三段で見る: **地形**(地理院DEM)+**建物**(PLATEAUの実測高)+**樹冠**(木の高さ)。
    - 樹冠のデータは**Meta/WRIの1m樹冠高マップ**(CC-BY 4.0・認証不要・公開)を第一候補にする
      (第140に富士山域のタイルの実在を確認済み。クラウド最適化GeoTIFFなので必要な窓だけ読める)。
      控え: JAXA AW3D30(登録が要る)・ETH全球樹冠高10m(直接URLは未確認)。
    - 観測者は**地上1.5m**を標準にする(アプリの観測点高さの既定値1.5m化と揃える)。
    - 自分の立っている画素の木や建物は「遮るもの」に数えない(足元の木で自分が塞がれる誤判定を防ぐ)。
    - 樹冠の考慮は**オン/オフできる**(依頼者memo「植生の高さは、オプションで、ON OFFできる」)。
  - 計算の進め方(依頼者・第136)
    - 推し山を中心に**10km四方(=z15タイルの10×10のかたまり)に区切り、順番に計算**する。
      メモリを使い過ぎないための区切り方。
    - 全画素を見ずに、**見える可能性のある帯だけ**を先に絞る(候補帯プレフィルタ。辻メッシュで
      実証済みの方位角の索引の延長)。
    - この計算は**MCPで宙の辻を動かして**行う(MCPは計算の指揮者=順番出し・進み具合・中断と再開。
      言葉の決めごとはMCP対応のデッサンと一緒に確定)。
  - 結果の形(静的資産)
    - 一度計算した結果を**タイルごとの画像(見える=1/見えない=0)+計算条件のメモ(JSON)**として配布する
      (形式の細部は未決)。アプリはこれを読み込んで表示するだけ。
    - **ユーザーの入力は反映しない**(第138確定)。実地の見え方(木・天気)の答え合わせは推し山サイトの
      投稿(可視判定5パターンなど)が担う。
  - 島の一覧
    - 「見える」画素の**8近傍のつながり**を1つの島とする(案)。小さすぎる島を除く閾値は未決。
    - 島は**面積の大きい順**にリストにし、タップでその島へ地図が移動する。
    - **ピンは可視マップには置かない**(第142変更: ピンは推し山サイトで、ユーザーが写真から投稿する)。
- デザイン概要
  - 入口: 位置情報メニューの「可視マップ」トグルボタン(デッサン`01-location.md`の23.)。
  - アプリ側は**見るだけ**(計算はMCPで別に行う)。
  - 0段目:
    - 1. 「可視マップ」ラベル(太字・左寄せ)
    - 2. 「▼」(右寄せ)。タップで開閉・初期は閉じている。
  - 1段目:
    - 3. 範囲ラジオ「:60km / :100km / :300km / :700km」(初期値: 60km)。
  - 2段目:
    - 4. 「:可視タイル」チェック(初期値オン)=塗りの表示/非表示。
    - 5. 「:樹冠あり」チェック(初期値オン)=樹冠込みの版と地形だけの版の切替(資産が2種類あるとき)。
  - 3段目:
    - 6. 注記「標高・建物・木の高さからの概算です。現地では見えないこともあります」。
  - 4段目:
    - 7. 推し山検索テキストボックス:
      - スペース区切りで複数指定できる
      - プレースホルダー: 推し山名、都道府県名
  - 5段目:
    - 8. 検索条件AND指定ラジオボタン:ラベル名は「:AND」
      - スペース区切りをAND指定で検索できるようになる。
    - 9. 検索条件OR指定ラジオボタン:ラベル名は「:OR」
      - スペース区切りをOR指定で検索できるようになる。
  - 6段目:
    - 10. 「:百名山」チェックボックス:
      - 検索対象に百名山を含める
    - 11. 「:二百名山」チェックボックス:
      - 検索対象に二百名山を含める
    - 12. 「:三百名山」チェックボックス:
      - 検索対象に三百名山を含める
    - 13. 「:百高山」チェックボックス:
      - 検索対象に日本百高山を含める
  - 7段目:
    - 14. 検索ボタン
      - 推し山名や都道府県名、もしくは、空白で、チェックボックスで指定した山を検索して、リストアップできる。
  - 8段目:
    - 15. 「表示オプション:」ラベル:
  - 9段目:
    - 16. 「:山頂ピン」チェックボックス:
      - 選択している山の山頂にピンを立てます。
    - 17. 「:全展望ピン」チェックボックス:
      - 選択している山の全てが見える場所にピンを立てます。
- デザイン詳細
  - 地図上に可視タイル表示と検索結果の山リストと可視タイルの「島」リストがある。
  - 検索ボタンを押下したら、辻メッシュ検索のように、山リストが表示され、その「山リスト」の山名のチェックボックスを選択すると、選択した山名の可視タイルマップが金色で地図上に表示され、また、辻メッシュ検索の詳細リストのように、選択した山名の「島リスト」が表示され、リストは、2段になります。
  - 山リストで、複数の山を選択した場合は、複数の可視タイルを地図上に重ねて表示します。
  - 山リストで選択した山の山頂には、黄色のマーカーが立ちます。
  - それぞれの山の島がどの山に所属するのかがわかるように、山ごとに島の輪郭を色分けして表示します。これを山色と呼びます。
    - 色分けの基準色は、選択した順番で決まります。17山目は、1山目に戻って循環して配色します。
      - 1山目:表示天体のスタイル設定で使用している赤色
      - 2山目:表示天体のスタイル設定で使用している桃色
      - 3山目:表示天体のスタイル設定で使用している橙色
      - 4山目:表示天体のスタイル設定で使用している黄色
      - 5山目:表示天体のスタイル設定で使用している黄緑色
      - 6山目:表示天体のスタイル設定で使用している緑色
      - 7山目:表示天体のスタイル設定で使用している水色
      - 8山目:表示天体のスタイル設定で使用している青色
      - 9山目:表示天体のスタイル設定で使用している藍色
      - 10山目:表示天体のスタイル設定で使用している紫色
      - 11山目:表示天体のスタイル設定で使用している薄紫色
      - 12山目:表示天体のスタイル設定で使用している茶色
      - 13山目:表示天体のスタイル設定で使用している焦茶色
      - 14山目:表示天体のスタイル設定で使用している白色
      - 15山目:表示天体のスタイル設定で使用している灰色
      - 16山目:表示天体のスタイル設定で使用している黒色
  - 複数の山が選択されている状態で、可視タイルが重なっている場合は、重なっている山の数だけ、辻メッシュ検索のように、金色のグラデーションで表示して、その可視タイルの場所から、複数の山が見えることがわかるように、辻メッシュ検索のように、マウスでホバーするとその眺望できる山の数表示し、その可視タイルをクリックすることで、その可視タイルが含まれる島がリストアップされ、複数の山が選択されている数と同じ数の山が見える場所(つまり、選択している山が全て見える場所)の可視タイルには、辻メッシュ検索のように、金色と赤色のタイルを表示します。
  - 島リストの島をチェックボックスで選択すると、その島の輪郭が点滅し、どの島を選択しているかどうかがわかるようになります。
  - 島リストの島を複数選択している場合は、それぞれの島の輪郭を点滅させて、分かるようにします。
  - 山リストの表示項目は、以下のようになっています。各見出しで、ソートできます。
    - 項番
      - 検索結果を番号づけしたのもの。
    - 山名称
      - 山名称の漢字名称
    - 山名称の読み
      - 山名称の読みをひらがなで表示。
    - 所属の都道府県
      - 複数ある場合は、複数記載する。
      - ソート順は、北から南、東から西です。
    - チェックボックス
      - その行の山を選択していることを表す。
      - 見出し行には、全て選択、全て解除のチェックボックスがある。
    - 山頂三角点の緯度
      - 山頂に三角点があれば、その緯度を表示する。生値。
    - 山頂三角点の経度
    　- 山頂に三角点があれば、その緯度を表示する。生値。
    - その山に含まれる島の数
      - 例:1個
    - 可視マップの範囲
      - 例:60km
    - 樹冠のあり、なし
  - 島リストの表示項目は、以下のようになっています。各見出しで、ソートできます。
    - 項番
      - 各島を番号づけしたのもの。
        - 島の中心を、北から南、東から西、で順序づけて、番号づけしたもの。
    - 所属山名称
      - 島が所属する山名称の漢字名称
    - 所属山名称の読み
      - 島が所属する山名称の読みをひらがなで表示。
    - 島の中心が所属する都道府県
      - 複数ある場合は、複数記載する。
      - ソート順は、北から南、東から西です。
    - チェックボックス
      - その行の島を選択していることを表す。
      - 見出し行には、全て選択、全て解除のチェックボックスがある。
    - 島の中心の緯度
      - 島の中心の緯度を表示する。生値。
    - 島の中心の経度
    　- 島の中心の緯度を表示する。生値。
    - その島の面積
      - 例:100m2
    - 可視マップの範囲
      - 例:60km
    - 樹冠のあり、なし
  - コントロールメニュー
    - 辻メッシュ検索のように、コントロールメニューを配置する。
    - 1段目:
      - 3. 範囲ラジオ「:60km / :100km / :300km / :700km」(初期値: 60km)。
    - 2段目:
      - 4. 「:可視タイル」チェック(初期値オン)=塗りの表示/非表示。
      - 5. 「:樹冠あり」チェック(初期値オン)=樹冠込みの版と地形だけの版の切替(資産が2種類あるとき)。
    - 3段目:
      - 6. 注記「標高・建物・木の高さからの概算です。現地では見えないこともあります」。

- 推し山サイトとの分担(第142確定: 静的/動的)
  - **可視マップ(静的)**: 島の形と場所・見える/見えないの塗り。計算して配る。
  - **推し山サイト(動的)**: 1〜2週間以内と2年先の推し辻(◎○)の日時、観測点のピン(ユーザー投稿:
    写真の位置情報+写真+レビュー+評価+共感)、検索、ユーザー履歴。詳細は`07-oshiyamasite.md`。

### 進め方(第142・依頼者決定):
- 可視マップと推し山サイトは**デッサンまで**進める→先に**可視マップの実装だけ**を行う→
  宙断面・宙検索・宙統計・宙の会合のデッサンと実装→その後に推し山サイトの実装。

### 未決事項(実装デッサン時に):
- 静的資産の形式(画像の量子化・圧縮・JSONの項目)と置き場所。
- 島の最小画素数の閾値、島リストに出す情報(面積・代表点)。
- 樹冠マップの実データの品質確認(富士山域で実在の森と値を突き合わせる)。
- PLATEAU建物の高さの取り込み方(属性の実測高か、メッシュから焼くか)と整備都市外の扱い。
- MCPの言葉の決めごと(操作・進み具合・結果の受け取り)=MCP対応デッサンと一体で。
