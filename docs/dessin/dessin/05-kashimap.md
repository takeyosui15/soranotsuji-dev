## 可視マップメニュー
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------

(第2版: 2026-08-29 第140ラウンド起草。第1版[第137]の依頼者の文字起こしに、第138の検品・
第139のCesium検討[推奨案は依頼者承認済み]・第140の樹冠データ源実測を織り込んだ完成版の叩き台。
第1版の全文はgit履歴に残る。依頼者の言葉/AI提案/未決の区別は引き続き明示する)

### 目的:
- 推し山(目的点)が「どこから見えるか」を、地図上のタイルとして一望できるようにする。
- 推し山ダイヤモンド・推し山パール・推し山天の川の観測地探し(辻メッシュ検索)の前段として、
  そもそも見える場所の全体像(可視マップ)を提供する。
- データは**一生物の静的資産**として一度計算して配布し、アプリは閲覧の場とする。

### 概要:
- 機能概要
  - 可視マップの定義(依頼者・第136〜138)
    - 目的点(推し山)が見えるかどうかを計算したタイルの地図。**対象は基本リスト
      (百名山・二百名山・三百名山)のみ**(公開Myリストからの追加は推し山サイトの持ち場)。
    - 判定の観測者は**地上1.5m**を標準とする(観測点高さの既定値1.5m化[本体todo]と揃える)。
    - 扱う範囲は**最大700km四方**(富士山は紀伊半島の潮岬から観測された実績があるため)。
      **60km四方、100km四方、300km四方、700km四方**で選択できる。
  - 単位系(第138確定: z15タイル整列)
    - 計算・配布・(推し山サイト側の)黒塗りの単位は**地理院標高タイルのz15タイル**
      (256×256画素)に整列させる。
    - z15タイルは赤道で1.223km四方、**北緯35〜36°でほぼ1.00km四方**(北海道約0.89km・
      沖縄約1.09km)。画素間隔は約3.9m(北緯35°付近。元データDEM5Aは5m格子)。
    - **緯度で0.89〜1.09kmに伸縮する**性質を仕様として明記する(徒歩の見立て15〜30分は
      誤差の範囲)。
    - 10km四方の分割キュー(依頼者・第136)は**z15タイルの10×10ブロック**として実装する
      (北緯35°で約10km四方。計算結果・計算途中のメモリが爆発しない、の狙いのまま)。
  - 計算方式
    - 判定コアは既存の統一可視判定(_visJudgeCore=地球の丸み+大気差k込み・第116)を再利用する。
    - **候補帯プレフィルタ**(第138で仕様昇格): 全画素を舐めず、辻メッシュで実証済みの
      方位角ビン索引・プレフィルタの延長で「見える可能性のある帯」に絞ってから判定する。
    - 遮蔽面(見えるかの判定に使う高さ)は三段重ね(第139推奨・依頼者承認):
      1. **地形**: 地理院DEM(z15チェーン: DEM5A→5B→5C→z14)。
      2. **建物**: PLATEAUストリーミング(b3dm)の**実高**。属性表(bldg:measuredHeight)の
         パース追加、またはメッシュから画素毎最大高さ(建物DSM)を焼いてDEMに重ねる。
         3D風ビル(地図の擬似高さ100/40/10m)は表示専用で判定に使わない(第139確定)。
      3. **樹冠**: 樹冠高マップをDEMに加算して概算(下記データ源)。
    - 観測点画素自身の樹冠・建物は遮蔽に数えない(足元の木で自分が塞がれる誤判定の防止。AI提案)。
  - 樹冠データ源(第140実測)
    - 一次候補: **Meta/WRI「High Resolution Canopy Height Maps」(約1m解像度・CC-BY 4.0・
      AWS Open Dataで公開・認証不要)**。第140ラウンドに実測: タイル索引(tiles.geojson・
      全球56,145クアッドキー)から富士山域=クアッドキー133002121を特定し、
      chm/133002121.tif(Cloud-Optimized GeoTIFF・約561MB)の実在をHTTPで確認済み。
      COGなので必要窓だけの範囲読みができ、全量ダウンロード不要。
    - 控え①: JAXA AW3D30(30m DSM)−地理院DEMの差分。ただし第140実測で旧配布URLは
      移転案内へリダイレクト=**取得にはユーザー登録の壁**があり、経路の再調査が要る。
    - 控え②: ETH全球樹冠高10m(2020)。直接URLは第140時点で未確認(403)。
    - 注記: 樹冠マップの撮影年代・急斜面での精度は限界があり、最終的な答え合わせは
      推し山サイトの可視判定5パターン統計(一生物のデータ)が担う(依頼者設計)。
  - 静的資産(第138確定: ユーザーの入力は反映しない配布物)
    - 一度計算した成果物(タイル)を配布し、アプリはfetchして表示するだけ。
    - 形式(案・AI提案): z15タイル毎の256×256画像(可視=1bitまたは見え代の量子化)+
      計算条件(k値・データ源の版・計算日)のメタJSON。詳細な形式・量子化・圧縮は未決。
    - この広くてたくさんある可視マップの作成は、**MCPで宙の辻を操作**して行う(依頼者・第136。
      MCPは計算の指揮者: キュー投入・進捗・中断再開。語彙はMCP対応デッサンと一体で確定)。
  - 島とピン
    - タイルの閉区域「**島**」がどこにあるか全て分かるように、**リストから引ける**(依頼者)。
    - 島の定義(案・AI提案): 可視画素の**8近傍連結**成分。ノイズ除去の最小画素数の閾値は未決。
      リストの並び順(案): 面積の大きい順。
    - 島内の**登山道上に、タイル毎のピン**を置く(依頼者・第138で**登山道に限る**と確定。
      理由: 富士山のように高い山は標高だけの判断だとどこからでも見えてしまうため。道路は外す)。
    - 登山道データ源は未決(候補: OSMの道データ[ODbLのため派生データの扱いに注意]・
      国土数値情報。第1版から継続の調査項目)。
- デザイン概要(第2版の叩き台・要検品)
  - 入口: 位置情報メニューの「可視マップ」トグルボタン(デッサン`01-location.md`の23.)。
  - アプリ側は**閲覧専用**(計算はMCP/バッチの持ち場)とする(AI提案・要確認)。
  - 凡例:0️⃣:段抜き、1️⃣:1行目、以下同様
  - 0段目:
    - 1. 「可視マップ」ラベル: 太字、左寄せ
    - 2. 「▼」ラベル: 右寄せ
    - 共通事項: タップで開閉。背景グレー、不透明。初期状態: 閉じている。
  - 1段目:
    - 3. 「推し山:」ラベル+推し山リストボックス:
      - 基本リスト(百名山・二百名山・三百名山)から選択。初期値: 未選択(選択で表示開始)。
  - 2段目:
    - 4. 「範囲」ラジオボタン群: :60km / :100km / :300km / :700km(四方)。初期値: 60km。
  - 3段目:
    - 5. 「:可視タイル」チェックボックス(初期値オン): 可視タイルの重ね描画の表示/非表示。
    - 6. 「:島ピン」チェックボックス(初期値オン): 登山道上のピンの表示/非表示。
  - 4段目:
    - 7. 注記ラベル: 「標高+建物+樹冠からの概算です。現地では木や気象で見えないことがあります」
      (推し山サイトの可視判定統計の説明と対にする)。
  - 5段目〜:
    - 8. 島リスト(面積順): 行タップでその島へ地図ジャンプ。
  - (段組み・文言は叩き台。第3版で依頼者検品を織り込み確定)
- 推し山サイトとの持ち場分担(第138確定)
  - 可視マップ(アプリ): タイル計算と閲覧・島リスト・登山道ピン・基本リストのみ。
  - 推し山サイト: 2年先の◎○(先取り計算の構想は07-oshiyamasite.mdの台帳参照)・
    カスタマイズ(オフセット角・45度/90度・線)・公開Myリスト追加・可視判定5パターン統計・
    観測点の1km黒塗り(z15タイル整列)。
