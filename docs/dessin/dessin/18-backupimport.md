## バックアップメニュー
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------


### 目的:
- Homeボタン、推し山ボタン、表示天体、My天体、My観測点、My目的点、My辻検索、設定のリストの一括バックアップをすることで、データの保護と、デバイス間のデータの同期を可能とするものとする。
### 概要:
- 機能概要
  - JSON形式のファイルで、一括バップアップとインポートができる。
  - appState、ローカルストレージとの整合性が保てる。
- デザイン概要
  - 設定メニューの下に配置する。
  - 0段目:
    - 1. 「バックアップ/インポート」ラベル:
      - 太字、左寄せ
    - 2. 「▼」ラベル:
      - 右寄せ
    - 共通事項:
      - タップすると、バックアップメニューが開閉する。
      - 背景グレー、不透明
      - 初期状態:閉じている。
  - 1段目:
    - 3. 「バックアップ」ボタン:
      - このボタンを押下すると、実行する前に、確認メッセージ「ローカルストレージの内容をバックアップファイルに全て出力しますか？」（window.confirmで、OK、キャンセル）が表示される。
        - 確認メッセージの後にブラウザからJSONファイルをダウンロードできる。
      - ファイル名にバックアップ実施日時を含める。
        - soranotsuji-app-バックアップ-YYYYMMDD-hhmmss.json
      - ローカルストレージの中にローカルストレージの最終更新日時を含める。
      - ローカルストレージの情報をJSON形式でバックアップする。
    - 4. 「インポート」ボタン:
      - JSONファイルから一括インポートできる。
      - このボタンを押下すると、実行する前に、確認メッセージ「ローカルストレージの内容をバックアップファイルから全て上書き入力・登録しますか？」（window.confirmで、OK、キャンセル）が表示される。
        - 確認メッセージの後にファイル選択ダイアログが開いて、デバイス内のファイルを選択できる。
      - appState、ローカルストレージと整合性が取れる。
      - My観測点、My目的点の地図上のマーカーも更新される。
  - 2段目:
    - 5. 「Googleドライブ」ラベル：
      - ローカルストレージの内容を保存しているユーザのGoogleドライブの保存先を示す。
  - 3段目:
    - 6. 「ログイン」ボタン:
      - Googleアカウントにログインするボタン。
      - 制約:ログイン中は非活性。
    - 7. 「ログアウト」ボタン:
      - Googleアカウントからログアウトするボタン。
      - 制約:ログインしていない場合は非活性。
  - 4段目:
    - 8. 「宙の辻フォルダ名:」ラベル:
  - 5段目:
    - 9. 宙の辻フォルダ名テキストボックス:
      - テキストボックス
      - 初期値:/soranotsuji-宙の辻
      - 制約:/で始まること
  - 10段目:
    - 10. 「登録」ボタン:
    - 宙の辻フォルダ名を変更した時に、反映させるためのもの。
    - (第132ラウンド・依頼者の疑問への判断: 「追加」「解除」ボタンは設けない)
      - フォルダはIDと目印(appPropertiesのsoranotsuji=root)で追跡しており(ensureSoraFolders)、
        ユーザーがドライブ側で名前変更・移動をしても連携はそのまま保たれる=関連づけ直しの操作が不要。
        この旨をヘルプ(バックアップ/インポート/Googleドライブ同期の節)に明記した。
      - 「追加」(任意の既存フォルダの採用)はフォルダ選択UIと目印の付与が必要になり、
        目印付きフォルダが2つできると再発見(driveFindByMarker)がどちらを拾うか不定になる危険がある。
      - 「解除」は旧フォルダの目印除去とセットでないと、次回の再発見で元のフォルダに戻ってしまう。
        作り直したい場合はドライブ側でフォルダをゴミ箱に入れれば、次回保存時に新規作成される(trashed=falseで除外)。
  - 6段目:
    - 11. 「設定フォルダ名:」ラベル:
  - 7段目:
    - 12. 設定フォルダ名テキストボックス:
      - 読み取り専用テキストボックス
      - 初期値:/(宙の辻フォルダ名)/設定
  - 8段目:
    - 13. 「Myセットフォルダ名:」ラベル:
  - 9段目:
    - 14. Myセットフォルダ名テキストボックス:
      - 読み取り専用テキストボックス
      - 初期値:/(宙の辻フォルダ名)/Myセット
  - 10段目:
    - 15. 「Googleドライブ最終更新日時:」ラベル
  - 11段目:
    - 16. Googleドライブにsoranotsuji-app.jsonを保存した最終更新日時を表示
      - 例:2026年02月09日(木) 19:32:16
  - 12段目:
    - 17. Googleドライブにローカルストレージを保存した容量を表示
      - 例:ローカルストレージ: 1,024KB
  - 13段目:
    - 18. 水平線
  - 14段目:
    - 19. 「地理タイル:」ラベル:
  - 15段目:
    - 20. 「合計件数:」:地理タイルと同じ文字サイズで、黒字細字。
      - 地理タイルの合計件数を表示する。
    - 21. 「合計容量:」:地理タイルと同じ文字サイズ、黒字細字。
      - 地理タイルの合計容量を表示する。
  - 16段目:
    - 22. 「最終更新日時:」:地理タイルと同じ文字サイズ、黒字細字。
      - 例:「2026年08月23日(日) 15:23:07」
  - 17段目:
    - 23. 注記:「自動キャッシュなので、定期的に全削除してください。」
  - 18段目:
    - 24. 「地理タイルを全削除」ボタン:サイズを横幅一杯にする
      - キャッシュしてある地理タイルの全削除ボタン。
  - 19段目:

      - 標高タイルの合計容量を表示する。
  - 22段目:
    - 29. 「最終更新日時:」

  - **第158(v1.97.0)で実装**(13〜24段目):
    - 地理タイル=地図の地理院タイル(標準・淡色・写真・ベクトル)。MapLibreのソースのURLを `gsicache://https://cyberjapandata.gsi.go.jp/...` にし、addProtocol('gsicache') で端末の店(IndexedDB `soranotsuji-maptiles`/tiles。鍵=URL・{size, buf, savedAt}・404は size 0 の「無し」の印)を先に読み、無い時だけ fetch して店へ(20秒で諦める)。
      店の合計が1GBを超えたら新しく貯めない(表示はする)。OSMは店を通さない(地理院のタイルだけ)。404は MapLibre の既定と同じく status 404 の例外で静かに「タイル無し」。
    - 標高タイル=可視マップのその場計算の店(IndexedDB `soranotsuji-kashimap`/tiles。鍵 kind/z/x/y・PNGのバイト列)を、標高グラフ/辻メッシュ/可視判定(_getTileImageData→_demTileLoad)と宙の窓の地形ワーカー(sora-terrain-worker.js)も先に読むようにした。無ければ取って店へ。
    - 国土地理院の回答(2026年10月・問合せ): 「端末にキャッシュされ、当該端末にだけ地図が表示されるのであれば、出典の明示(申請不要)で利用できる」。出典の明示は地図の帰属表示(地理院タイル)とヘルプに。
    - 件数・容量・最終更新日時は _mtRefreshBackupRows()(バックアップの節を開いた時(toggleSection)・全削除の後・店に入れた後は1.5秒まとめて。節が閉じている間は数えない)。数え方は索引(size・savedAt)の鍵カーソルだけ=本文(PNGのバイト列)を読まない(地理タイルの店 v2・標高タイルの店 v3 で索引を足す。第158のレビュー: 1GBの店を値カーソルで舐めるとタイルが貯まるたびに表示が止まる)。ヘルプ(バックアップ/インポート)に「地理タイル / 標高タイル (端末の控え)」の項。
    - 「無し」(404)の印の寿命は30日(SORA.TILE_STORE.MISS_TTL_MS)。過ぎた印は取り直す(地理院は後からタイルを足すことがある)。本体(gsicache://・_demTileLoad)・宙の窓の地形ワーカー・可視マップのワーカーの4箇所とも同じ。標高タイルの取得の失敗は1回で諦める(呼び元の失敗の印に任せる。従来の Image 読みへ落ちるのは「取れたのに復号できない」時だけ)。
    - 22段目の注記「可視タイル作成後は、標高タイルは不要です。いつでも、全削除可能です。」は開錠時(?kashimap=1)の文。可視マップを封鎖しているリリース版では「可視タイル」が画面に無いので、applyFeatureLocks() が「標高グラフ・辻検索・辻メッシュ・宙の窓の計算に使う控えです。いつでも全削除できます(次に使う時に国土地理院から取り直します)。」に書き換える(ボタンの説明と確認文も同様。第158のレビュー)。
      注: 標高タイルの店はオフラインの標高グラフ等にも使うようになったので、可視タイル作成後も「不要」とは限らない(文の見直しは依頼者の判断=回答その156)。
  - **第183(v1.99.0)・デッサン35 段1**(24段目の下。標高タイルの「全削除」ボタンの次):
    - 25段目: 水平線
    - 26段目: 「本体の控え(オフライン用):」ラベル(km-sub。ツールチップ=宙の辻の本体(画面・プログラム・同梱データ)の端末の控え(Service Worker)。電波の無い所でも宙の辻を開けるように、版ごとに控えます。新しい版は、全部そろって確かめてから入れ替わります)
    - 27段目: 「合計件数:」(id backup-shell-count)「合計容量:」(backup-shell-size)=標高タイルと同じ見た目
    - 28段目: 「版:」(backup-shell-ver。例: v1.99.0。複数の版が残っている時は「, 」で並べる)
    - 29段目: 注記「削除すると、次に開く時に通信して作り直します(電波の無い所では開けなくなります)。」(デッサン35 Q6・依頼者「注記に書くで良い」)
    - 30段目: 「本体の控えを削除」ボタン(横幅一杯。確認文の後に Cache Storage の sora-shell-* と Service Worker の登録を消す=_swClear。次に開く時に登録し直す)
    - 件数・容量・版は _mtRefreshBackupRows が地理/標高と一緒に数える(_swStat: 控えの各応答の content-length の合計)。
    - **第184(v1.99.1)・デッサン35 段2/段3**(Googleドライブの行の下=地理タイルの上に「端末のデータ」の節、各店の行に最終使用/使用率/上限(MB)、建物・可視マップ資産・天気の節を標高タイルの下に):
      - 「端末のデータ:」ラベル / 「全体: 使用 / 割当(ブラウザの割当)」(navigator.storage.estimate) / 「永続: はい(消されない)/いいえ」(persisted)・「前回の整理: 日時」 / 整理の状態の文(整理中: 店 N/M件 → 整理しました: N件・MB) / 「今すぐ整理」「永続化を要求」(2分割) / 「設定(登録内容): KB・使用率 %(上限はブラウザの約5MB)」
      - 地理タイル・標高タイル: 既存の行の下に「最終使用: 日時」「使用率: %」と「上限(MB): [テキストボックス](既定 1024)」(空欄=既定。端末ごと=localStorage の `sora_store_caps`。`soranotsuji_` の接頭辞ではないのでバックアップ・ドライブ同期に乗らない=第184の反証レビュー C7)
      - 「建物(PLATEAU):」合計件数/合計容量・最終更新日時(第185)・最終使用/使用率・上限(MB)・「建物タイルを全削除」(店 soranotsuji-bldg。都市モードの b3dm と tileset.json)
      - 「可視マップ資産:」合計件数/合計容量・使用率・上限(MB)(自動では消さない。封鎖中は節ごと隠す=backup-assets-block)
      - 「天気の控え:」合計件数/合計容量・使用率・上限(MB)・「天気の控えを削除」(TTL 2時間を過ぎた物は片付けで消える)
      - 件数・容量・最終使用・%は _mtRefreshBackupRows が一括で埋める(索引の鍵カーソルだけ。本文は読まない)。片付けは sora-store-worker.js(デッサン35 §4)。
