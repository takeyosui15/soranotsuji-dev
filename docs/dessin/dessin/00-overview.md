# デッサン（dessin）
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------
## 共通仕様
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------


### 目的:
- 作っていただくClaudeさんに、迷わず、高品質なものを作っていただくための基準
- 私からは、分かりやすい仕様書を書くのが「愛」だと思う。
### 概要:
- Webアプリの設定は、ローカルストレージの唯一のキー「soranotsuji_app」以下にまとめる。
- Webアプリの状態を管理するための変数は、唯一のキー「appState」以下にまとめる。
  - SSOT(Single Source of Truth：信頼できる唯一の情報源)の実現
- Webアプリをテストするためにローカルストレージを削除(リセット)するためのページ(reset.html)を作成する。
- コーディング規約
  - 命名規則
    - グローバル定数:UPPER_SNAKE_CASE
    - グローバル変数:PascalCase
    - 定数:UPPER_SNAKE_CASE
    - 変数:camelCase
    - 関数名:camelCase
    - CSS:kebab-case
  - UIテキスト・コメントは**日本語**で記述
  - コミットメッセージも日本語（`feat:` / `fix:` / `style:` プレフィクス使用）
  - XSS対策として `escapeHtml()` を使用（ユーザー入力をDOMに挿入する際は必須）
  - **構造とスタイルの分離**: インラインスタイル（`style="..."`）は使用せず、CSSクラスで定義する。HTML/JSには構造のみ、`style.css`にスタイルを記述する。
- ラベル名やプレースホルダーの内容は、日本語が多いので、半角・全角に気をつける。
- 計算処理が重い場合は、クルクルやプログレスバー、進捗状況を伝え、なるべく内部で並行処理したり、キャッシュを作って再利用したりするように工夫する。

## 画面全体
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------


### 目的:
- スマホでも、操作・確認しやすいように工夫をする。
### 概要:
- 左上の上段:地図の種類を変更できるコントロールパネルがある。
  - 地図の種類は4種類。国土地理院の標準地図、写真地図、淡色地図、OpenStreetMapの地図。
- 左上の下段:地図をズームできる拡大縮小ボタンがある。
- 左下:地図の縮尺がわかるスケールがある。
- 右下:地図の著作権が見えるようにする。
- 右上:宙の辻のコントロールパネルがある。
### 仕様詳細:
- 宙の辻のコントロールパネル
  - タップすると、メニューが開いたり閉じたりする。
  - 中のメニュー(位置情報メニューなど)は、長くなっても表示できるようにスクロールできること。
  - 表示項目
    1. 宙の辻のロゴ画像(PNG画像)
    2. 「宙の辻 - Sora no Tsuji」ラベル
    3. Googleアカウントのログインリンク/同期状態を表示するアイコンボタン。
    4. 「？」ボタン
       - ヘルプボタンで、ヘルプウィンドウが開く。
       - 丸いボタン
    5. 「▼」ラベル
  - タップして、メニューが閉じている時は、最小化したいので、「 - Sora no Tsuji 👍」は表示しない。
  - 初期状態:閉じている。
- 3. Googleアカウントのログイン状態・リンク/ローカルストレージの状態・同期状態を表示するアイコンボタン:
  - ユーザのGoogleアカウントにログインしていない時は、🈚️アイコンを表示する。
    - このアイコンを押下すると、ユーザのGoogleアカウントにログインできる。
  - ユーザのGoogleアカウントにログインしていて、ユーザのGoogleドライブとローカルストレージの同期が取れている時は、👍アイコンを表示する。
    - このアイコンを押下すると、ユーザのGoogleドライブとローカルストレージの同期を取る。
  - ユーザのGoogleアカウントにログインしていて、ユーザのGoogleドライブとローカルストレージの同期が取れていない時は、👎アイコンを表示する。
    - このアイコンを押下すると、ユーザのGoogleドライブとローカルストレージの同期を取る。
  - ユーザのGoogleアカウントにログインしていて、ユーザのGoogleドライブとローカルストレージの同期を取っている間は、以下のアイコンをアニメーションで示す。
    - 🕛🕧🕐🕜🕑🕝🕒🕞🕓🕟🕔🕠🕕🕡🕖🕢🕗🕣🕘🕤🕙🕥🕚🕦
  - ユーザのGoogleドライブにローカルストレージの内容を保存したファイルをsoranotsuji_app.jsonとする。
  - ユーザのGoogleアカウントにログインしていて、ユーザのGoogleドライブのsoranotsuji_app.jsonのファイルの状態を⭕️❌アイコンで表示する。
    - soranotsuji_app.jsonの量量が膨大になるので、通信が途中で途切れた場合で、soranotsuji_app.jsonが壊れてしまった場合でも、復旧できる様にする。
      - 例えば、reset.htmlで保存したローカルストレージのバックアップファイルをそのままGoogleドライブに保存すると、復旧できるとか。バックアップインポートメニューでバックアップしたファイルをそのままGoogleドライブに保存すると、復旧できるとか。
    - soranotsuji_app.jsonのファイル構造にバージョン番号を付与して、バージョン管理をする。
    - soranotsuji_app.jsonは、JSON形式なので、内部のツリー毎に更新日時の管理ができる様にする。
      - スキーマバージョン+更新日時をツリー毎に持つ
      - 内部ツリーの末端の更新日時を根元の更新日時に伝搬する様な感じか何かで、ツリーの更新管理で最適な管理方法で管理する。
      - トップレベルのセクション毎(myList, myObservation, myTarget, myBody, 設定類…)に `{ schemaVersion, updatedAt }` を持たせ、書き込み時に「そのセクションのupdatedAt」と「ルートのupdatedAt」の2つを更新するだけで、「末端→根元への伝搬」の実用形になります。v1の同期はファイル丸ごと差し替えなのでルートのupdatedAtしか使いませんが、セクション毎に持っておけば、将来のセクション単位マージに移行できます。

  - ユーザのGoogleアカウントにログインしてるか、していないかだけを一定時間おきに確認する。
  - アイコンの状態遷移と動作
    - 状態遷移

                1. soranotsuji_app.jsonのチェック中:🕛

      - ①:ログインされているか、されていないかをチェックする。
        - 静的サイト(バックエンドなし)では、Google Identity Services(GIS)のトークンモデルを使うことになり、アクセストークンの有効期限は約1時間です。ログイン状態は「手元のトークンがまだ有効か」を端末内で見るだけで判定でき、毎分Googleに問い合わせる必要はありません。
        - また、バックグラウンドでの自動トークン更新は、ブラウザのサードパーティCookie制限(特にiPhoneのSafari)で失敗しやすいため、**「同期ボタン押下などの操作時に、トークンが切れていたら取り直す(必要ならポップアップを出す)」イベント駆動型**を推奨します。デッサンの「一定間隔で更新チェック」はローカルの時刻比較のみで行い、通信を伴う処理はユーザ操作時に寄せる形が安全です。

      - ②:soranotsuji-app.jsonの破損状態のチェック
        - Googleドライブは、API経由で上書きしたファイルも**旧版(リビジョン)を自動保持**します(標準では30日または100版まで)。壊れた場合は直前の版に戻せるので、これが第一の保険になります。
        - さらに堅くするなら、「①一時ファイル(soranotsuji-app.tmp.json)としてアップロード → ②Drive側のmd5Checksum/サイズを照合 → ③本番ファイルへ反映」という2段階更新にすると、通信断でも本番ファイルは壊れません。
        - JSON内部に自身のバイト長かハッシュを含めておくと、読み込み時にも破損検知ができます。
        - reset.htmlのバックアップファイルをそのままDriveに置ける構造(=ローカルストレージ全体のJSONと同一構造)にしておく案は良いと思います。復旧経路が2本になります。

## reset.html仕様
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------


### 目的:
- デバッグ作業や、何らかの問題があった場合にユーザーがローカルストレージをリセットできる様にする。
### 概要:
- 機能概要
  - ローカルストレージの容量を表示
  - ローカルストレージの内容を表示
  - ローカルストレージのバックアップボタン
    - ファイル名にバックアップ実施日時を含める。
      - soranotsuji-app-バックアップ-YYYYMMDD-hhmmss.json
  - ローカルストレージに復元ボタン
  - ローカルストレージの消去ボタン
  - トップページに戻るリンク
