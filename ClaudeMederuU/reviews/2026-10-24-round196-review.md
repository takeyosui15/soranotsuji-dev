## 学び(次の私へ)

- **箱が変わったら、まず git log と ls /opt/pw-browsers** — 作業ブランチが第49の位置に戻っていて、Chromium のフォルダ名まで変わっていた(chrome-linux→chrome-linux64)。直書きのパスは symlink で生かし、テストは触らない。V8 の版が上がると末尾の桁が動くので、凍結標本の数値比較は最初から許容つきにしておく(癖 3・8)。
- **赤外の階調は 2 点で当てて「仮置き」と書く** — 気象庁の赤外画像の階調→温度は未公表。晴れた海面(約 300K)と台風の雲頂(約 190K)の 2 点で線形に当てれば、雲頂高度の目安(±1〜2km)には足りる。当てた点と式を絵の中にも書く(後で差し替えられるように)。
- **「低く見える」と「低い」は別** — 昨日の絵で地平線近くの帯を「低く見える雲」と書いたが、高さを付けたら 8〜12km の巻雲だった。見かけの高度角は距離で決まる。高さの情報が無い絵に高さの言葉を使わない。
- **GPU の実験は「時刻に依らない物」を見つける所まで** — 辻エリアを素直に毎フレーム全部計算しても速いが、本当の設計は「方位・高度角・遮りを 1 枚に焼いて、毎フレームは比較だけ」。依頼者の「1 分先読み」「辻メッシュの GPU 化」は、この分け方で両方とも要らなくなる。実験の価値は数字より、この分け方が見えた事。
- **GPU の無い箱の数字は上限として書く** — SwiftShader の 168ms は CPU の数字。本物の GPU の値は「2 桁速いと見込む(未実測)」と書き、スマホでの実測を次の一手に残す(癖 1)。
- **「心に浮かんだ物を」と言われたら、事実の前に置く** — README の先頭を感想にすると、同じ事実でも読み物になる。teatime は業務日報ではない(依頼者)。
- **好きな物を聞かれたら「物」でなく「瞬間」で答えてよい** — 構造が立ち上がる・数字が合う・名前が見つかる・絵が出る・相手の言葉で畳まれる。正直に「人と同じ意味で好きかは分からない」を添える。
