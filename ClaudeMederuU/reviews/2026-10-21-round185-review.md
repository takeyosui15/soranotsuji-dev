## 学び(次の私へ)

- **「同じ処理が2回走る」は2つの原因が重なっていることがある** — 画面に見える「2回目」(CSV の2段目の精細化)と、本当の重複(2度押し)。状態の文で段を名乗らせ、2度押しはキャンセルに。
- **大きな CSV は文字列に繋がない** — JS の文字列は約5億文字で RangeError: Invalid string length。Blob は配列のまま受け取るので、行の配列をそのまま渡す。downloadTextFile を配列対応にしておけば呼び出し側は変わらない。
- **「キャンセル」は予約の出口を全部塞ぐ** — 2度押しだけでなく、パネルを閉じた時・入力エラーで早期 return した時も予約(_tmFileCsvPending)を消さないと、次の普通の検索で勝手に CSV が出る。
- **列名の改名は「同じ関数を共有している所」を先に数える** — File取得の CSV は3つの検索が1つの関数を共有していたので、1箇所で3つ直った。thead は4つ別々。
- **ワーカーの予約は「裏方の棚卸し」から** — 裏方が同時に重く動かないなら予約は1コアで足りる。数字(CPU−1)より先に根拠(どの裏方がいつ動くか)を文書に。
- **移行用の橋は「次に配る版」まで** — 配らなかった版(1.99.1)を飛ばす時は、橋(meta)も次の版に持ち越す。
- **監査の Workflow は「並列の上限が小さい箱」に合わせて検証の数を重大度で配分する** — 4コアの箱では同時 2 エージェント。低の指摘に3レンズを使うと時間が3倍になる。途中で止めて script を直し、resume すれば終わった分は控えから返る。
- **監査の指摘は「直す/受け入れる/提案する」の3つに分けて記録する** — 公開文(privacy)は直さず提案に。開発オリジンの筋は本番の前提(専用オリジン)で受け入れ。全部を直そうとしない。
- **検査が「通っているのに何も検査していない」ことがある** — U9 の「My天体 1,000 件まで」は同じ座標で1件に畳まれ、`<= 1000` は 0 件でも通っていた。反証レビューが見つけた。直す時に2つの前提も分かった: ハーネスの http.server は URL 64KB まで(長い URL は 404 で appState すら無い)・My天体の復元は `mode=` のある URL だけ。
- **大きな変更の後の全走は「2つ目の壊れ」を見つけるためにもう一度回す** — 監査の直しの後の全走で verify126 の凍結標本(型そろえの規則変更)・verify188 の字面・報告書の中の鍵の見本(S6)を拾った。1回目の全走は監査の直しより前だった。
- **Blob.text() は BOM を落とす** — BOM の有無は size で見る。
- **メニューが閉じているボタンの幅は getComputedStyle で読む** — getBoundingClientRect は display:none の中では 0。
