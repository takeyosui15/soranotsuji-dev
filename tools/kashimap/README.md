# tools/kashimap — 可視マップの山データ(名山対応表)

可視マップ(デッサン`docs/dessin/dessin/05-kashimap.md`)の「山リスト」の元データを作る道具です。
地理院「日本の主な山岳標高(1003山)」を土台に、百名山・二百名山・三百名山・百高山の印を
**索引番号**で結び付けます(山名は同名異山・表記ゆれがあるので、キーにしません)。

## 出力の列

連番・索引番号(地理院)・表示山名(名山リストでの表記)・表示よみ・地理院山名・山頂名・標高(m)・種別(三角点/標高点/測定点)・
都道府県・緯度・経度・百名山・二百名山・三百名山・百高山(印は`1`)・別名(検索用。地理院表記や括弧内の別称)・
照合方法・確認状態・備考。

確認状態の意味:
- `自動一致` = 名前/よみ/標高/座標が揃って一致(検品不要)。
- `目視確認済` = 表記違い(利尻岳=利尻山 など)をAIが目視で確認したもの。備考に根拠。
- `手動指定` = 自動照合が外した/迷ったものをAIが指定(燧岳→燧ヶ岳＜柴安嵓＞、黒岳→水晶岳 など)。
- `依頼者確認済` = 依頼者が検品で決めたもの(第147)。峰の選択6件(谷川岳=オキノ耳・九重山=中岳・飯豊山=本山・那須岳=茶臼岳・
  安達太良山=本峰・丹沢山=丹沢山)と、地理院1003山に無い三百名山4座(二岐山・諏訪山・藤原岳・吾妻山[広島])の座標
  (Wikipedia座標→地理院DEM5Aの最高画素→依頼者がヤマレコで確認)。
- `その他` = どのリストにも無い地理院の山。

## 検品の仕方(依頼者向け)

見るファイルは **`meizan-map.csv` の1つだけ**です(`src/`の2つは原本なので触りません。地理院CSVはShift_JIS、JSONはWikipediaの転記)。

1. `meizan-map.csv` をExcelやNumbersで開き、「確認状態」の列で **「要確認」(6行)** と **「地理院に無し」(4行)** に絞る。
2. 「要確認」の6行は「どの峰をその山とするか」の選択。候補と地図へのリンクは `kenpin-2026-09-21.md` にまとめてある。
3. 「地理院に無し」の4行は座標の確認。地理院DEMで山頂の画素を探し直した座標を `kenpin-2026-09-21.md` に載せてあるので、
   リンク先の地図で山頂に落ちているかを見る。
4. 答えは `docs/order.md` に「1:A 2:A …」のように書くか、`kenpin-2026-09-21.md` の `[ ]` に `x` を付けてコミット。
   反映(スクリプトの手動指定表への書き込みと再生成)はClaudeが行う。CSVを直接直す必要はない。

## viewshed.js(段2: 計算の道具)

```
node --max-old-space-size=6000 tools/kashimap/viewshed.js --id 368 --range 60 [--zoom 15] [--k 0.132] [--obs 1.5] [--concurrency 6] [--check 3000] [--preview 1200] [--outline 3000]
```

- 入力: `--id`=data/mountains.json の索引番号(地理院に無い4座は x1〜x4)。`--range`=範囲(km四方)。`--zoom`=DEMのズーム(15=約3.9m画素)。
  `--k`=大気差の係数(静的資産はアプリの標準値0.132で固定・Q23)。`--obs`=観測者の高さ(m・既定1.5)。
- DEMは dem5a→5b→5c(z15)→dem_png(z14を2倍)の順に取り、`cache/` に置く(2回目からはネットに行かない)。同時取得は `--concurrency`(既定6)。
  地理院のタイルサーバーへの負荷を考え、1つの山の1回の実行より多くを続けて回さない(60km四方=3,721枚≈330MB)。
- 判定: 山頂から窓の縁の全画素へ光線を伸ばし(R2)、見かけ高度角 (h−d²/(2Reff)−hS)/d の最大を更新しながら外へ歩く。
  観測者は地上+1.5m。式と観測点側の除外(10m)はアプリの統一可視判定(_visJudgeCore)と同じ。
  目的点側の除外は「山頂部の広がり」(山頂から `--summit-drop`[既定120]m以内の高さの画素が山頂から最も遠い距離。`--summit-search`[既定3000]m内。
  `--excl-target` で指定も可)。山頂の1点だけを目的点にすると火口の縁や山頂の肩に隠れて「見えない」だらけになるため(富士山で実測)。
  山頂の標高は3×3画素のDEM最大。
  `--check N` で、アプリと同じ歩き方(z15半画素刻み)で標本N画素を判定して一致率を出す。
- 出力(`out/<id>-<range>km-z<z>-terrain/`): `visible.bin`(1bit・行優先・W×H)・`islands.json`(島の索引: 項番=北→南の固定番号・
  画素数・面積km²・代表点[緯度,経度]・bbox・山頂からの距離km)・`islands.geojson`(大きい島は外周・小さい島は画素の四角)・
  `meta.json`・`preview.png`(見える割合を金色の濃さに。山頂は赤)。
- まだ無いもの: 樹冠(Meta/WRI)・建物(PLATEAU)・輪郭の穴・PMTiles化・小→大の段階計算と水平線フィルタ(段2後半)。

## 再生成

```
python3 tools/kashimap/build-meizan-map.py      # 対応表 meizan-map.csv
python3 tools/kashimap/make-mountains-json.py   # アプリ用 data/mountains.json
```

原本の取り直し(年1回・地理院の版が上がった時):
- 地理院ページ https://www.gsi.go.jp/kihonjohochousa/kihonjohochousa41139.html からCSVを保存し、`src/`へ日付つきで置く。
- 注意: www.gsi.go.jp はTLSの「安全な再交渉」に未対応で、OpenSSL 3系のcurlは既定で接続を拒む。
  ブラウザやmacOSのcurlでは問題ない。OpenSSL 3系で取る時は、証明書の検証はそのままに、
  `Options = UnsafeLegacyRenegotiation` だけを許した設定ファイルを `OPENSSL_CONF` で渡す(`fetch-gsi-1003zan.sh`)。
- Wikipediaの4ページは `src/meizan-lists.json` の`_source`にURLを記載。表の構造が変わったら転記部分を直す。
